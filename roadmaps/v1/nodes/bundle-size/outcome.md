# Outcome: bundle-size

## Built

- `pnpm --filter benchmark size` (`benchmark/size/size.mjs`): builds talata (`pnpm build`), then bundles talata and the reference stack with esbuild and prints minified, gzip and brotli sizes for a Node build and a browser build. Flags: `--no-build` (reuse `dist`), `--json`, `--keep <dir>` (write the bundles). `esbuild` is a new devDependency of `benchmark`.
- Both sides use the same settings: ESM, ES2020, minified, one file, tree shaking, GFM on, 1 KB = 1000 bytes. talata entry: `fromMarkdown(text, { gfm: true })` from `talata`. Reference entry: `mdast-util-from-markdown` with `micromark-extension-gfm` and `mdast-util-gfm`. The `node` build resolves the `node` condition, the `browser` build the `browser` condition. Only the reference's `decode-named-character-reference` and talata's own entity table differ between the two.
- A `browser` export condition in `packages/talata/package.json` for `.` and `./unified`, pointing to `dist/browser/`. `tsdown.config.ts` now has two configs: the normal build, and a second one that swaps `./entities` for `src/inline/entities.browser.ts` (decodes through `document.createElement('i').innerHTML`, no table, same method as the reference's `index.dom.js`).
- A compact Node table in `src/inline/entities.ts` (generated by `scripts/generate-entities.mjs`): entries sorted by name, each stored as one base-36 digit for the length of the prefix shared with the previous name, the rest of the name, and the value, with no separators (no value holds an ASCII letter or digit, except `fjlig` = "fj", which is set in code). Gzip of the table: 11.1 KB to 9.5 KB.

## Numbers

Measured on main at bceab1a plus this branch, before perf-pass merges.

| build | stack | minified | gzip | brotli |
| --- | --- | --- | --- | --- |
| node | talata | 92.3 KB | 32.6 KB | 28.8 KB |
| node | mdast + gfm | 118.2 KB | 35.9 KB | 30.7 KB |
| browser | talata | 69.1 KB | 22.5 KB | 20.1 KB |
| browser | mdast + gfm | 82.5 KB | 23.8 KB | 20.8 KB |

Gzip ratio: 0.91 in Node, 0.94 in the browser. Before this node: Node 100.5 KB / 34.7 KB gzip (0.97), browser the same file (1.46, because the reference's browser build uses the DOM and has no table).

Rerun after perf-pass merges: `pnpm --filter benchmark size` (it rebuilds talata first; the numbers are about the margin, so quote them from a run on the merged main).

## Deviations

- Edited `packages/talata/scripts/generate-entities.mjs` (not in the brief's paths) so the generator writes the new table format. The old output would have been overwritten by the next run otherwise.
- Added `packages/talata/test/bundle-size.test.ts` (3 tests): the table decodes all 2,125 names to the same value as the reference's `decode-named-character-reference`, and rejects the names it rejects.
- `entities.ts` was regenerated from a local `entities.json` rebuilt from the previous table, because the sandbox had no network. The new test compares against the reference's `character-entities` list, so a wrong table would fail. Rerunning the generator with the network should give the same file.
- `packages/talata/tsdown.config.ts` now exports an array of two configs. The second sets `clean: false`; the first cleans `dist` including `dist/browser`, and I saw `dist/browser` survive two rebuilds, but the order between the two configs is not documented.

## Gotchas

- The DOM decoder (`entities.browser.ts`) is not exercised by a test: no DOM library is installed. It copies the reference's logic. Check it once in a real browser, or add jsdom/happy-dom if a test is wanted.
- The margins are thin (about 1.3 KB gzip in the browser, 3.3 KB in Node). Code added by perf-pass or the extension nodes can erase the browser margin. The biggest non-table modules (minified): emphasis 5.2 KB, link 4.7 KB, autolink-literal 4.4 KB, core/blocks 4.4 KB, blocks/html 4.1 KB.
- The test hooks `emphasisPaths` (emphasis.ts) and `workSteps` (lines.ts) are still in the public bundle; they cost a few hundred bytes. perf-pass removes them, as the brief says.
- `pnpm build` output now holds `dist/browser/`. `files: ["dist"]` already ships it.
- The corpus is not needed by `size`. I symlinked `benchmark/corpus` (git-ignored) for the tests only.
