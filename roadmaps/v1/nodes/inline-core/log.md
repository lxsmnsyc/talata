- Review round 2.
  - Emphasis bug: `_**a****b*_`. `**` and `****` fail the rule of three, `****` then shrinks to `***` by pairing with `*`, and micromark resolves the inside of the outer `_` pair again (insideSpan), where `**` and `***` now pair. The linear path dropped the delimiters between a pair for good. Now each pair queues the delimiters left between it as a list of its own and pairs that list later. A delimiter drops out of a list once, so the work stays linear (step counts grow 8.0 times for 8 times the input on every growth case). Order between queued lists does not matter, because pairing a list never touches delimiters outside it.
  - Committed differential test: xorshift32 generates 8000 inputs of 3 to 7 `*`/`_` runs between letters, spaces, punctuation and link parts. Both paths must give the same tree (`emphasisPaths.mixedOnly` forces the general path). With the re-pairing disabled it fails (on `____a****](u)___](u)**a****b*a_`); with it, it passes. The earlier free-form token generator did not hit the bug.
  - Growth tests now count work (`workSteps` in lines.ts: emphasis opener search and inside lists, label lookup characters, code span scan, raw HTML states, bracket side stack) instead of timing. Each case asserts that steps grow less than 12 times for 8 times the input. With openers_bottom disabled, `* a`, `_a*b ` and `**_ a` grow 64 times and fail.
  - Line ending positions after a lookahead. In micromark the text tokenizer gets one line at a time. A line ending's end point skips the next line's container prefixes only when that line had already been fed, that is, when some construct looked into it. Evidence: `>\`\n>_a_`ends the text at 4;`> a\n> _b_`ends it at 3.`>\`\n> _a_`ends it at 5, after the quote prefix, not at the content.`reach()`in lines.ts records the furthest range a code span, raw HTML or link scan looked into.`endRange`(text.ts) then ends the line ending, or the hard break over it, at`containerEnd()` of the next line.
  - `containerEnd()` needs where container prefixes end. Paragraphs now record `line.start` and `partialTab` for every continuation line with whitespace after its containers, and register the list in `lineIndents`. This also makes code spans, raw HTML and reference labels in list items exact; the change request's list-item gap is closed for paragraphs. `paragraph.ts` lost its `[`-only condition; definitions read the same list and still pass.
  - Scratch fuzz with every registered block and 13 container styles (none, `> `, `>`, `>\t`, lists with 2, 3 or 4 columns of indent, `> - `, `- > `, tabs), multi-line inline content: 80k documents, 0 differences. The PRNG there is now xorshift too.
