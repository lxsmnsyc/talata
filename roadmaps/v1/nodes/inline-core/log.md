# Log: inline-core

- 2026-10-28: started. No existing inline rules (`inlineRules` was empty), so the work was not done before.
- Read micromark-core-commonmark 2.0.4 (attention, label-end, label-start-*, code-text, character-reference, character-escape, hard-break-escape, autolink, html-text), the destination, title, label and whitespace factories, and mdast-util-from-markdown 2.1.0 handlers. Rules follow those state machines, not the spec text.
- Found: code spans, raw HTML (after skipping 3 columns) and reference `label` fields keep the whitespace left on a line after container prefixes, split-tab columns included. Ranges do not carry that. Wrote `contracts/parser-core-v3-inline-core.change-request.md` (path given by the orchestrator) and a guess in `lines.ts` (wrong only inside list items).
- micromark's attention resolver runs every span resolver on the events between a matched pair. Emphasis does the same through `resolveSpan(state, open + 1)`, so GFM strikethrough can pair inside emphasis and nothing pairs across it. Reference: `*a ~~b* c~~` gives emphasis; `~~a *b~~ c*` gives delete. The second depends on resolver order, which is gfm-inline's call.
- With GFM, `~` next to a `*`/`_` run counts as "other" for flanking (micromark `attentionMarkers`). Implemented in emphasis.ts behind `options.gfm`.
- `[^a](b)` with GFM is a plain link in the reference (`_hiddenFootnoteSupport` is not set), so link.ts has no footnote special case.
- Entities: the WHATWG list's 2125 semicolon names equal character-entities 2.0.2 exactly (checked by script). Table generated by `packages/talata/scripts/generate-entities.mjs`.
- Spec sections: 348 of 357 inline-section examples pass; the 9 left need indented/fenced code, HTML blocks, lists or multi-line definitions.
- Scratch fuzz (not committed): random inline-heavy documents restricted to paragraphs, ATX headings, breaks and single-line definitions. About 220k compared over several seeds, plain and GFM: 0 differences.
- Corpus check (scratch): top-level paragraphs and headings with the same span in both trees, skipping references and GFM nodes: 5843 compared, 5 differ, all GFM autolink literals.
- Pathological inputs: unclosed `<!--` per line was quadratic (4.8 s on 35 KB). Added per-leaf caches for unclosed comments, CDATA, declarations, instructions and code span sizes: now under 25 ms for each 20k-repeat input tried.
