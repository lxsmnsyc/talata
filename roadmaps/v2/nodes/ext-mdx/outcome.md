# Outcome: ext-mdx

## Built

`talata/mdx`: `mdx()` (named and default export of `packages/talata/src/mdx.ts`) returns `cachedExtension('mdx', ...)` with `name: 'talata:mdx'`. It gives the tree of `mdast-util-from-markdown` with `micromark-extension-mdx` 2.1.0 and `mdast-util-mdx` 3.0.0, positions included: `mdxJsxFlowElement`, `mdxJsxTextElement`, `mdxFlowExpression`, `mdxTextExpression`, attributes (`mdxJsxAttribute`, `mdxJsxExpressionAttribute`, `mdxJsxAttributeValueExpression`). Bad syntax throws `MdxError` (exported from `talata/mdx`): `reason` and `place` as the reference's `VFileMessage`, `message` is `reason + ' at ' + place` (`1:5` or `1:1-1:4`), or the reason alone when the reference has no place. Paths below are under `packages/talata/src/ext/mdx/`.

- `index.ts`: the extension. Block rules `mdxFlowScope`, `mdxFlow`; inline rules `mdxChunks`, `mdxLabel`, `mdxJsxText`, `mdxExpressionText`; transform `mdxJsxBuild`; `disable: { block: ['codeIndented', 'html'], inline: ['autolink', 'html'] }` (contract v4).
- `scanner.ts`, class `Scanner`: the expression scanner and the tag scanner, one state machine ported state by state from `factoryTag` (micromark-extension-mdx-jsx 3.0.2) and `factoryMdxExpression` (micromark-factory-mdx-expression 2.0.3). Modes `TEXT_TAG`, `TEXT_EXPRESSION`, `FLOW` (a line of tags and expressions). It reads one line at a time: `run()` returns `DONE`, `NOK` or `MORE` (a line ending was consumed), and the caller feeds the next line with `feed(pos, end, last, kept, lineStart, lazy)` or `feedEnd(at)`. Every crash message of `factoryTag` and the expression factory is in it (`crash`, `lazyTag`, `lazyExpression`, `eofExpression`).
  - Expression end: state `EXPRESSION_BEFORE`, on `}` with `size === 0`, calls `expressionEnd()`. That is where `micromark-factory-mdx-expression` calls acorn (`mdxExpressionParse`). `value`, `expressionStart` and `expressionKind` (`EXPRESSION_ALONE`, `EXPRESSION_ATTRIBUTE`, `EXPRESSION_VALUE`) say what is being read. Braces are counted in `EXPRESSION_INSIDE`.
  - Values: an expression keeps the whitespace after a line ending minus 2 characters (`kept`: `linePrefix(state, range, 2)` in text, `keptWhitespace(line)` in flow); quoted attribute values keep every line ending and drop the whitespace after it.
- `jsx-text.ts` (`<`, 100) and `expression-text.ts` (`{`, 100): inline rules through `inline.ts` `scanInline`, which feeds the ranges of the leaf.
- `flow.ts`, `mdxFlow` (block, `<{`, 320, interrupts paragraphs): the flow construct, a concrete leaf. A line that holds only tags and expressions; after an expression only a tag may follow (the reference's flow expression tries only JSX after itself). A construct that does not end on its line keeps its scanner, takes the next lines through `continue`, and is the only open construct at a time (`pending`). `flow-scope.ts`, `mdxFlowScope` (block, no triggers, priority 1, never starts): records where a lazy line after an open construct starts.
- `tags.ts`: markers. A text tag is a marker node in phrasing content (`talataMdxTextTag`); a line of flow tags is one marker in flow content (`talataMdxFlowTags`, positioned to the end of the line with its trailing whitespace, as list items end there). `talataMdxNodes` holds the nodes of a failed construct (below).
- `build.ts`, transform `mdxJsxBuild`: turns markers into elements as `mdast-util-mdx-jsx` 3.2.1 does while `mdast-util-from-markdown` walks events. It walks the tree in document order with the two stacks of the reference (open nodes with their micromark token type, open tags) and throws all six `mdast-util-mdx-jsx` errors (`Unexpected closing slash`, `Unexpected attribute in closing tag`, `Unexpected self-closing slash`, `Unexpected closing tag`, `Expected a closing tag ... before the end of`, `Expected the closing tag ... either after the end of`). `tokenOf` maps mdast types to token types (`blockQuote`, `listItem`, `atxHeading`, `tableHeader`, `gfmFootnoteDefinition`, `directiveContainerLabel` ...). An image keeps only `alt`, so its label is parsed again without the `!` (`labelNodes`).
- `order.ts`: which error the reference throws first. micromark tokenizes in passes; with `d` container directives around, flow errors are pass 2d - 1, text errors pass 2d + 1 plus one per text directive label around. Flow errors outside container directives throw at once; the others wait and the transform throws the first.
- `reread.ts`, `prefixes.ts`, `lookahead.ts`: a flow construct that fails on a later line (text after its last tag). micromark is still trying it, so the lines it took are read again as flow without containers: `interruptAt` finds blank lines and the constructs that interrupt the paragraph (headings, fences, thematic breaks, setext underlines, tables, math and directive fences, flow tags and expressions, which may throw). `OpenMdxFlow.rereadNodes` makes the nodes: paragraphs through the paragraph prefix rules (definitions), setext headings, and leaf blocks read by their own rules (fenced code and math left open become `inner`, which takes the next lines). The paragraph it interrupted goes on (`interrupted`, `join`): a paragraph of the block parser is copied once and its node dropped; a failed construct before it leaves its node without text (`deferred`) and hands its arrays over, so a chain of failures stays linear. `lookahead.ts` decides it before a table body row. `prefixes.ts` finds where a lazy line starts after the containers.
- `entities.ts`: character references in quoted values, as `parse-entities` with `nonTerminated: false`. `chars.ts`: name and whitespace classes.
- Wiring: `./mdx` export in `package.json`, `src/mdx.ts` in `tsdown.config.ts`, `talata/mdx` in `benchmark/size/size.mjs`, `'mdx'` in `test/parsers.ts` (`ExtensionName`), `test/fuzz/ext.ts`, `test/ext-api.test.ts`, `test/ext-api-bundle.test.ts`. Dev dependencies `micromark-extension-mdx` ^2.1.0 and `mdast-util-mdx` ^3.0.0.
- Fuzz hook `test/fuzz/ext-mdx.ts`, `ready: true`: matched elements, self-closing tags, fragments, expressions, attributes of each kind, tags across lines, and some broken syntax.
- Tests: `test/mdx-reference.test.ts` (255 inputs from the reference packages' tests, license note), `test/mdx.test.ts` (183 own cases, 196 fuzz failures, `MdxError`, the unified plugin, the corpus with `[mdx]` and `[frontmatter, math, directive, mdx]`, with and without GFM).

How acorn plugs in (ext-mdx-acorn): give `Scanner` an optional acorn and options. In `EXPRESSION_INSIDE`, stop counting braces when acorn is set (the reference counts only `}` then). In `EXPRESSION_BEFORE` at `}`, before `expressionEnd()`, parse `value` with `acorn.parseExpressionAt` as `mdxExpressionParse` does (spread and empty rules by `expressionKind`); on failure keep the `}` as data and go on (`lastCrash`), and throw it at the end of file. The positions to map acorn's errors back are `expressionStart`, the line starts fed through `feed`, and the `kept` whitespace. ESM is a new flow construct beside `mdxFlow` (`import`/`export` at a line start); the flow-error order in `order.ts` and the failure re-read in `reread.ts` apply to it as to flow tags.

## Deviations

- `src/ext/math/flow.ts`, `src/ext/directive/leaf.ts`, `src/ext/directive/container.ts`: outside the owned paths. `line.indent >= 4` became `line.indent >= line.indentLimit` (four places), and the two `createLine` calls in `container.ts` pass `line.indentLimit`. With MDX, indented code is off and micromark lifts the 3-column limit of math and directive fences too (the gotcha in the mdx-core outcome); the `--all` fuzz found `    ::x[]`. Without MDX nothing changes.
- `test/parsers.ts`: with `mdx` in the names, a syntax error on either side becomes a root with no children and `data.mdxError` (the message), so the fuzzer and the tests compare errors as trees, and a case where both throw matches only when the messages match. `test/fuzz/check.ts` is unchanged.
- `src/ext/mdx/build.ts` re-parses image labels with `parseInline` (a read-only core helper), and `flow.ts` reads `size` and `indent` of open list items and container directives through `'size' in block` checks, as ext-directive does.
- `src/gfm/table.ts` (core, main entry): a header row that starts with `<` is read as HTML only when block HTML is registered (`hasHtml`). With MDX the reference reads it as a JSX flow attempt, which fails, and the row stays the header (`a\n<div>||\n-|-`). Output without an extension that turns HTML off does not change.
- No change request: contract v4 was enough.

## Gotchas

- Every 1M fuzz run before the last found new classes, almost all in two areas: which error comes first, and where a lazy line error points when containers, container directives and the end of the text meet (`prefixes.ts`). A new one is most likely there.
- The error order is measured, not derived from micromark's source (`order.ts` comment). A new kind of chunk (a new extension with labels or nested documents) needs its pass number checked against the reference.
- A failed flow construct is the hard part: its lines are read again without containers, while talata has already put them through the containers. `reread.ts` emulates the flow re-read for the constructs the fuzz produced; others (an HTML-like construct of a new extension, a nested list marker inside a tag's quoted value) are read as paragraph text.
- Known gap: when the failed lines hold a container directive opener (`:::x`) that is not closed among them, and the paragraph read before it has no syntax error (a definition such as `[a]:\n{` takes it), the tree misses the directive and its content (`[a]:\n{a\n:::x\n}x\n`). `reread.ts` cannot open a container; its lines are skipped up to the fence. The error order in this shape is right (`{a\n:::x\n}x\n<`). Not found by the `--all` fuzz; a targeted generator for this shape finds it in about 3 of 100,000 documents.
- `chars.ts` keeps the reference's regular expressions (`ID_Start`, `ID_Continue`) for code units above ASCII: a table would add kilobytes, and like micromark it tests one UTF-16 unit at a time (`charCodeAt`, then `String.fromCodePoint`), so a surrogate half is never a name character.
- Image labels are parsed again from source: a label across lines in a quote takes its line starts after `>` and whitespace (`labelRanges` in `build.ts`), which is a guess.
- vitest without `NODE_ENV=production` loads the development build of `mdast-util-from-markdown`, whose asserts fail before the reference's own error on a tag left open in a link label. `pnpm test` sets it.
- Module state: `inline.ts` keeps one shared `Scanner`, `flow.ts` a shared one for first lines plus `pending`. Both are reset per parse or checked against the parse's state; parses are not reentrant.

## Proposed learnings

- When an extension throws, compare the reference's message and place as part of the tree (`data.mdxError` in `test/parsers.ts`) | the fuzzer then checks errors like trees, and a talata-only throw is a diff | packages/talata/test | yes
- Find micromark's error order by trying inputs, two errors per input in different chunk kinds | the pass structure is not visible from the extension's source | packages/talata/src/ext | yes (fuzz)
