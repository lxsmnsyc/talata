# Log: ext-directive

## 2026-11-02

- Branch `feat/directive` from `origin/main` (0647835). Nothing of the directive was on main: `src/directive.ts`, the subpath export and the fuzz hook were removed in 361462c.
- Reverted the directive parts of 361462c with `git apply -R` on those paths: export and devDependencies in `package.json`, the `tsdown.config.ts` entry, `src/directive.ts`, `test/parsers.ts`, `test/fuzz/ext.ts`, `test/fuzz/ext-directive.ts`, `test/ext-api.test.ts`, `test/ext-api-bundle.test.ts`, `benchmark/size/size.mjs`. The lock file came back the same way, so `mdast-util-directive` resolves to 3.1.1 (a fresh `pnpm install` picked 3.2.0).
- Ported from `feat/ext-directive` (c85cccf) as they were: `syntax.ts`, `entities.ts`, the leaf rule, the tests and the fuzz hook. The old build passed its 260 reference inputs on the current core before any change.
- Rebuilt:
  - Text directive labels parse in place with `parseInline` from the rule's `parse` (`labels.ts`). The deferred label pass, the image `alt` markers and the second literal autolink pass of `fixes.ts` are gone: the core transforms now see the labels.
  - Trailing spaces and tabs of leaf and container labels go back through the object queued with `state.inline`: its `children` setter appends them. No transform.
  - Container: `isContainer: true`, `startsContainer: false`, `acceptsLazy: false`. Inner blocks close with `state.closeOpenBlocks(state.getDepth(this), { keepsLineEnding })`. The blocks above the directive come from the `openChild` chain, checked with `getDepth`. No cast to `stack`, `containerIndex`, `container` or `closeTo`.
  - `containerStartsOff` is set to false while a directive is open and restored when it closes. The three `inside` rules are gone.
  - `directiveCode` and `directiveHtml` are gone: hook 5 leaves `state.paragraph` undefined.
  - `scopes.ts`: no patched `Set.add`. A directive takes out of `definitions` and `footnotes` what its own content added; at the first hook of the inline pass, a label still in the set has a definition outside every directive and stays known.
  - List item spread over blank lines inside a directive: a small transform (`spread.ts`), only when the parse made a container directive.
- Dead end: core `continuesOverEnd` asks the blocks inside the directive too, so a quote inside made the directive lose its final line ending (`:::b\n>$\n`). The directive now records that the empty line after the end reached it (`atEnd`): the containers around it continued.
- Gap in the v2 hooks: when a new container starts outside a directive that did not match the line, the core keeps the line ending of every block it closes, also inside the directive. The old build redefined `closeKeepsLineEnding` as an accessor. Now a block rule with no triggers (`directiveEnd`, priority 1) runs first on every line that is not blank, starts nothing, and closes the blocks inside each directive that will close, with the answer the reference gives. Nested directives: the answer for the blocks inside one is the AND over every closing directive from the outermost in. When it has to guess whether a container starts, it reads the line (`isContainerStart`).
- The lookahead whether the next line continues the directive (micromark's `nonLazyLine`) only counted quote markers. Now the directive keeps the prefixes of the containers around it (quote marker or columns of indent, read from the start line and every line with content) and replays them on the next line. This fixed the seed 5 failure (`>+ :::\t\n>\t```\n>\n>``). The seed 77 failure (`1.\n :::a\n * <!--\n `) was the last-line check: it must run after the directive's own indent is consumed, and the directive then keeps that indent in its end.
- `createEmptyLine` padded the whole text once per call; now once per parse.
- Fuzz rounds of 6 x 100,000 (3 seeds without GFM, 3 with) after each fix. Round 1: 5 failures, round 2: 17 (two of my changes were wrong, see below), round 3: 9, round 4: 3 classes left.
- micromark ends the content of a directive before a blank line only when the next line is lazy: the containers around do not continue and no container starts (`nonLazyLine`). A container start on the next line keeps the blank line inside. `continuesAfter` replays the prefixes of the containers around the directive on the next line and sets `lazyNext`; `isContainerStart` reads quotes, list markers (not thematic breaks) and, with GFM, `[^label]:`. Before a final line ending, in a quote, the content ends as before a lazy line (the old behavior; outside a quote it does not).
- Dead end: treating the end of the text after a final line ending as a non-lazy next line broke `>:::e\n>-\n>\n`; reverted.
- The prefixes are kept as columns of indent before each quote marker and after the last; a quote may carry up to 3 columns of its own, so each entry is the least indent seen so far. Indents that enclosing directives consume are left out.
- Where inner containers end on such a line: a quote at the line start unless a prefix inside the directive is on the line; lists and items at the line end when a container starts next or before the final line ending. List items get it through `closedAt`, since they ignore `closeEnd`.
- Spread transform: a nested list that ends after its line ending still holds the blank lines after it (the reference exits the list after them).
- Text directive label whose last line is empty: the line ending before it ends at the line start, unless a split tab leaves columns there.
- When the content of a directive ends on a line followed only by a final line ending or by a lazy line, the reference parses that line as a last line without line ending. The core decides "last line" from `line.end === line.text.length`. Two cases worked around: a line that holds only the markers of the quotes inside (`>:::9\n>>$$\n>>\n`: the directive closes the blocks inside keeping their line ending and takes the line), and kind 7 HTML on a lazy line (`directiveHtml`, priority 399, runs the core HTML rule and turns `keepsLazyContainers` off). Other leaves on such a line are not covered.
- First 1,000,000 run (seed 20261103, all features): 4 failures in 859 s. Fixed: `next` (a container starts on the next line) now comes from the lookahead instead of counting quote markers; a directive closed by a lazy line closes its content with `state.unmatched` off, so a table inside does not mark the line as a lazy body row (`>:::a[]\n>_||\n>-|-\n!|o\n-|-`); the kind 7 HTML case above.
- Second 1,000,000 run (seed 20261104): 13 failures, from the quote-only branch (it also ran on true last lines and outside quotes), `[^ ]:` read as a footnote start, and kind 7 HTML outside quotes. Fixed all three.
- Batch 6 x 170,000 (seeds 131 242 353 1464 1575 20261104): 5 failures. Fixed: a quote inside ends after the line only when a list item or footnote prefix inside comes before it on the line; the quote-only branch needs `lazyNext`.
- Definitions and labels: a text directive label sees definitions up to one level deeper than its leaf, never two (`:::9\n:::b\n[Foo Bar]:()\n:::\n:a[[Foo Bar]]` is text). The "one level deeper after the opening line" rule holds for leaves only. The offset in `Scope` is gone.
- Batch 6 x 170,000 (seeds 141 252 363 1474 1585 1696): 1 failure, `[^a]\n>:::x\n>[^a]:\n[^a]:`. The footnote rule adds its label at `start`, before `attach` closes the directive, so the directive hid the root definition. `directiveEnd` now closes the unmatched directives themselves too, before any other rule runs on the line.
- Third 1,000,000 run (seed 20261105): over 30 failures, nearly all `[^ e]:` after a directive: the early close used the footnote guess for the directive's own end, and the guess took a label with spaces. The label now has no whitespace and no brackets.
- Final 1,000,000 run (seed 20261106): 4 failures in 675 s, new classes again (directive in a list item or quote, blank or last line). Stopped here: each run finds new classes and the fix loop has run long. The acceptance fuzz criterion is not met.
