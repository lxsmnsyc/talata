# Outcome: ext-mdx-acorn

## Built

`mdx({ acorn, acornOptions })` (`packages/talata/src/mdx.ts`) gives the tree of `mdast-util-from-markdown` with `micromark-extension-mdxjs` 3.0.0 and `mdast-util-mdx` 3.0.0, positions included, without `data.estree`. `mdx()` without acorn keeps its behavior (same cached object, braces counted, no ESM). New exported types: `Options`, `Acorn` (`parse`, `parseExpressionAt`; options typed `never` so acorn's own signatures fit without importing acorn), `AcornOptions`. Options are checked as the reference does ("Expected an acorn instance ...", "Expected a proper acorn instance ..."). One extension per acorn and equal options: the key is built from plain values and keeps `undefined`, so `{ ecmaVersion: undefined }` is not `{}`; options holding functions or other objects make a new extension per call. Paths below are under `packages/talata/src/ext/mdx/`.

- `acorn.ts`: `createJs` merges options as the reference (`{ ecmaVersion: 2024, sourceType: 'module' }`, the caller's, then `locations: true`; acorn also gets `preserveParens` and an `onComment` array). `parseExpression` (`mdxExpressionParse`): empty and spread rules by expression kind, "Unexpected content after expression", the three spread errors, "Unexpected empty expression". `parseEsm` (`atEnd` of mdxjs-esm): the `var a,b` prefix of names imported before, `swallow`, "Unexpected X in code: only import/exports are supported" with a start-end place. `placeOf` maps acorn offsets back through stops, as `relativeToPoint`. `bindJs` and `jsOf`: the acorn of the parse in progress.
- `scanner.ts`: with `js` set, braces are not counted; at each `}` (`parsesAtBrace`) acorn decides; a failure becomes `lastCrash`, the `}` is data, and the end of file throws it. `code`, `stops` and `codeStart` collect what acorn reads (kept whitespace from the source, the columns of a split tab dropped; `virtualStart` keeps the stop of an empty chunk). `lastCrash` is reset for every expression.
- `esm.ts`: `createEsm` (block, `ei`, 310, no paragraph interrupt, column 1 only) and the leaf `OpenMdxEsm` (acorn at each line ending before a blank line and at the end of the content; a line ending at the end is read first as before a blank line, as micromark does). `createEsmHeader` (block, `|:-`, 749, GFM): ESM on the header row of a table that interrupts a paragraph; it asks the table rule, then takes the header and delimiter rows. `startsEsm`: a line read again that can start ESM (column 1, keyword, no directive opener left open before it). `reparse`: micromark parses ESM in container directives after all flow outside them, depth by depth; each ESM records the names it saw, and when they differ from that order the transform parses the document again with the right names (at most 16 rounds; depth + 1 suffice).
- `flow.ts`, in the re-read of fix-mdx-reread-container: `esmStart` finds ESM in the lines read again where flow starts again (after any span the re-read finds: a blank line, a leaf block, tags and expressions; or at the first line after a directive fence or other ESM), when no directive, table or open construct comes before it. ESM may also start on the header row of a table that interrupts a paragraph, and a body row that starts ESM ends the table. When a construct in the ESM data would throw as flow, it reads the spans again with `stop` at the ESM line (or after the delimiter row). It returns the spans with the line; `reread` then keeps the spans before it and calls `handOver` with `last` -2, which reads the lines from it through `readLineAt`, so the ESM rule starts there; the lines after the blank line where it parses go to a new block (`fresh`), read again as flow. `waitFor` treats the current line as the last when it ends the content (`isLastLine`), and passes an error on as a flow error: base bug, also with `mdx()`, `>:::a\n><_ b="\n>{c">)\n` gave a lazy line error at 4:1, the reference the end of file at 3:7. `keptOf`: the whitespace an expression keeps at the start of each line read again, from `raw`, for `interruptAt` and `waitFor`.
- `reread.ts`: `interruptAt` takes an optional `kept`, fed to the probe for each line after the first, and `stop`, the line from which nothing starts (ESM data); a table body row that starts ESM ends the table. Expressions read again across lines kept no whitespace after the line ending (masked by a text error without acorn; with acorn `` `\n{`\n<a b={//\n\t`}`}/> `` showed it).
- `index.ts`: with acorn, every rule and the transform are wrapped to bind the acorn to the source before they run, so the scanners in `reread.ts` and `lookahead.ts` use it.
- `lookahead.ts` and `order.ts`: when a construct on a table body row ends in text, the lines it read are rows for the reference, where no container starts. Flow errors on those lines in blocks deeper than the table's container are dropped (`quietFlowErrors`); flow constructs in the table's container still fail there. Base bug, wrong with `mdx()` on batch/v2: `|a|\n|-|\n<a\n>{b\n}>` threw a lazy line error at 5:1; the reference fails at 3:3.
- `flow.ts` `handOver`, table: when the header row is the construct's own first line, the rows now go to the block parser too, not only the header cells; the table body then takes the lines after the construct, and ESM can start on one of them (`{`\n-|\n`}x\na\nimport `). The block after a table is `fresh` too.
- `prefixes.ts` `prefixEnd`: in a directive's content, a lazy line that ends right after a quote marker and its space is lazy from its start only when that quote is outside the directive or the text ends there; a quote inside the directive with a line ending after it gives the place after the prefixes. Base bug, also with `mdx()` on batch/v2: `:::a\n>>{\n> \n` gave 3:1, the reference 3:3. And a tab that the directive's indent splits on the last line leaves its columns, so the lazy line starts after it (` :::a\n>=\n{\n\t`: 4:2, was 4:1; base bug too, found by the 1M fuzz with seed 20261127).
- Tests: `test/mdx-acorn.test.ts` (121 inputs of the mdxjs, mdxjs-esm and mdx-expression tests, spread inputs as `<x {…} />` and `<x y={…} />`, own and fuzz cases, re-read cases with and without acorn, ESM order across directives, acorn options, acorn without JSX, errors, option checks, caching, dependencies, the corpus with acorn, growth). `test/mdx-acorn-targeted.test.ts`: a generator for ESM in directives, under table rows and across blank lines; `}` in strings, templates, comments and regexes; acorn errors under quote, list and footnote prefixes with tabs; spreads on their own line. 4,000 documents by default, `MDX_ACORN_TARGETED=N` for more. Fuzz hook `test/fuzz/ext-mdx.ts`: ESM blocks and starts, acorn-sensitive expressions and attributes, bad ones rarer; `mdxjsEsm` in `nodeTypes`.
- Dev dependencies: `acorn` ^8.19.0, `acorn-jsx` ^5.3.2, `micromark-extension-mdxjs` ^3.0.0. `dependencies` is still `@types/mdast` only. Changeset `.changeset/mdx-acorn.md` (minor).

## Deviations

- `test/parsers.ts`: `ExtensionOptions.mdx` (`{ acorn, acornOptions }`) and an exported `acorn` (`Parser.extend(acornJsx())`). With acorn the reference side is `mdxjs({ acorn, acornOptions, addResult: false })`, so it makes no `data.estree`. `TALATA_FUZZ_ACORN=1` turns acorn on for MDX by default.
- `test/fuzz/cli.ts`: `--acorn` sets that variable (workers inherit it) and goes in the replay line. Failures with `--acorn` are not saved as fixtures, since `fuzz.test.ts` replays fixtures without acorn.
- Rebased onto fix-mdx-reread-container (e6ae43f). My earlier fixes in `prefixes.ts` (`quoteMissing`, `contentEndAt`) and `order.ts` (an error at the end of the text in an unclosed directive) are dropped: that node removed the probe's reads past the failed lines and fixed the same order case. The cases stay in `test/mdx-acorn.test.ts` and pass.
- No change request: contract v5 is enough.

## Stubs left

- None. `data.estree` stays parked (ext-mdx-estree). The caller's acorn `onComment` and `onToken` callbacks are not called; they belong to estree output.

## Gotchas

- Acorn is called at the same places as in the reference, so shapes quadratic there are quadratic here: many `}` after an open string or template in one expression, many blank lines inside failing ESM, many imported names (each ESM declares all names before it).
- `reparse` runs the later transforms of other extensions again on the new tree when `mdx` is not last in `extensions` (tested with `[mdx, directive]`).

## Proposed learnings

- When an extension takes a parser from the caller, bind it per parse to the source rather than passing it through every scanner | the re-read and lookahead scanners then get it | packages/talata/src/ext | no
- Write a targeted generator next to the `--all` fuzz for every new construct | it found classes that 1M `--all` runs missed | packages/talata/test | yes
